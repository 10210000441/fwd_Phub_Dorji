01 — Group selectors

One rule, several selectors

Separate the selectors with commas and the declaration block applies to all of them. Three rules become one, and they can never drift apart later.

The comma

A, B, C { }

The heading below, the sub-heading and the quote are coloured by a single rule — not three near-identical ones.

CSS
/* one rule, three targets */
h4,
h5,
blockquote {
  color: indigo;
}

/* the same idea, elsewhere */
input, textarea, select {
  font-family: inherit;
}

02 — Combinators

Four ways to say where

A combinator describes an element's position relative to another one. Change the character between two selectors and you change the question being asked.

Descendant

A B

A plain space means anywhere inside — depth is irrelevant, so the link wrapped in a <div> is caught along with the one at the top level.

CSS
.sidebar a {
  font-weight: 700;
}
Result — both links match
Link 1depth 1
Link 2depth 2

Child

A > B

> matches direct children only. “Team” is a child of the inner <ul>, not of .menu — so it never becomes a pill, no matter how much it looks like a sibling of the others.

CSS
.menu > li {
  display: inline-block;
  background: indigo;
}

/* .menu li — a space — would
   have caught "Team" too. */
Result — “Team” is skipped
  • Home
  • About
    • Team — not a direct child
  • Contact

Adjacent sibling

A + B

+ matches exactly one element: the very next sibling. This is how a lead paragraph or a form's spacing gets set without any extra class.

CSS
h4 + p {
  background: green;
}

/* real-world uses */
img + p     { margin-top: 0; }
label + input { margin-left: 8px; }
Result — only the first paragraph

First paragraph — matched

Second paragraph — untouched

Third paragraph — untouched

General sibling

A ~ B

~ keeps going: every matching sibling that follows, not just the next one. Same markup as above, one character different, three matches instead of one.

CSS
h4 ~ p {
  background: indigo;
}
Result — every following paragraph

Title

First paragraph — matched

Second paragraph — matched

Third paragraph — matched

The one-line version: a space asks “inside?”, > asks “directly inside?”, + asks “immediately after?”, and ~ asks “after, at all?”.
All four need a shared parent for + and ~ — siblings only. Neither can ever look backwards to a previous element.
03 — Classes & weight

Stacking classes, and the space that changes everything

One element can carry as many classes as it needs. In the stylesheet, whether you put a space between two class selectors decides if you are describing one element or two.

Multiple classes on one element

class="a b c"

A base class plus modifiers. The base carries the shape; each modifier changes one thing. Note the padding — it is written once in em, so the large button grows its own padding.

HTML
<button class="btn btn-primary">Save</button>

<button class="btn btn-primary btn-large">
  Buy now
</button>
Result

Requiring both classes

.a.b

No space means “one element that has both”. With a space it becomes a descendant selector and hunts for a .featured inside a .card — a completely different question, and the classic typo.

CSS
/* one element, both classes */
.card.featured {
  border: 2px solid gold;
}

/* the typo: a .featured INSIDE a .card */
.card .featured { ... }

/* and every card after the featured one */
.card.featured ~ .card {
  opacity: 0.6;
}
Result

!important

use sparingly

!important steps outside the specificity contest entirely. An id normally beats a class — but not against an !important declaration, as the heading below shows.

CSS + HTML
#demo-header { color: blue; }
.title { color: red !important; }

<h4 id="demo-header" class="title">…</h4>

/* the fair use: a utility that must
   win wherever it is dropped in */
.hidden { display: none !important; }

/* usually you just need to be more
   specific instead */
#buy-btn { background: red; }
Result — red wins

04 — Measurement units

Six units, six different questions

Every unit is relative to something — except one. Knowing what each answers to is the whole trick. The root font-size here is 16px.

px fixed

Absolute. Identical everywhere, relative to nothing — which is exactly what you want for a hairline border or a shadow.

32px
96px
160px
border: 1px · radius: 6px · shadow: 0 2px 4px

% of the parent

A share of the parent's own size. The three tracks below are the same width, so the fills read as proportions.

25%
50%
75%
25% of a 900px parent = 225px

em of this element's font

Relative to the element's own font-size. Both tags below share one rule — padding: 0.5em — and land on different pixel values.

14px → 7px padding 24px → 12px
0.5em × 14px = 7px  ·  0.5em × 24px = 12px

Because it looks at the nearest font-size, em compounds when nested:

1em here
1.2em inside
1.2em again — now 1.44×

rem of the root font

Relative to the <html> font-size only, so it never compounds however deep it sits. This is the unit for layout rhythm.

0.5rem = 8px · 1rem = 16px · 2rem = 32px · 3rem = 48px
24px ÷ 16 → font-size: 1.5rem

vw / vh of the viewport

A percentage of the browser window itself, ignoring every parent. Resize the window and the bar below moves with it.

50vw
50vw on a 375px phone = 187.5px

And vh for full-screen sections — always as min-height, so extra content can still grow the box instead of overflowing it:

min-height: 30vh

Which one, when

A working default for each job:

pxborders, radii, shadows
%widths inside a parent
empadding that tracks its text
remtype scale, spacing rhythm
vhfull-screen sections
vwdisplay type, with clamp()

CSS selectors and units summary
Syntax Reads as Matches
A, B group Both A and B — one rule, no duplication
A B descendant Any B inside A, at any depth
A > B child Only a B that is a direct child of A
A + B adjacent sibling The one B immediately after A
A ~ B general sibling Every B after A, same parent
.a.b both classes One element carrying both — no space
!important override Beats normal declarations, id rules included
